# Maria — Tasks, calendar, Academy and notifications

This document records the defaults Maria is implementing for the university
demo. They are deliberately small and can be extended after the first release.
The team only needs to review cross-feature interfaces and shared migration
ordering; these product defaults do not need a team vote.

## Decisions Maria has made

### Tasks

- A task can be one-time or repeat daily, weekly or monthly, with an interval
  from 1 to 52 and an optional final local date. Weekday/month-day pickers and
  arbitrary recurrence rules are out of this demo.
- Repeating tasks keep their original local time in the household time zone.
  A monthly date that does not exist in a shorter month clamps to that month's
  last day (Postgres interval behavior). Occurrences are materialized on demand
  in a bounded window; missed occurrences remain overdue and later ones still
  appear.
- Editing a series changes future open occurrences and preserves completed
  history. Archiving hides future work and keeps its history.
- Any current household member may mark an occurrence complete. The app records
  who did it; only that person may undo/correct their completion.
- Tasks may be unassigned. Unassigned reminders go to all current household
  members. If an assignee leaves, the task remains and the assignee becomes
  unassigned.
- Assigned tasks remind the assignee one hour before the due time; one hour
  overdue, notify the rest of the household. Unassigned task reminders go to
  all current members one hour before. Muting the task category is per-user.

### Calendar and notifications

- The first calendar is a monthly view with task, Feeding and Health filters.
  Each event links back to its owning feature; source records remain
  authoritative, avoiding duplicate calendar copies.
- Maria owns the calendar presentation and task reminder infrastructure.
  Feature owners retain ownership of their source records and supply a stable
  source ID, event title/time, optional assignee, destination route, and reminder
  time. Editing/deleting a source must update/cancel its event/reminder.
- Shared notification RPC contract: call `sync_household_notification` with a
  household, category (`feeding`, `health`, `walk` or `academy`), stable
  source-record ID, delivery kind, title/body, app-relative route, send instant,
  and either one current recipient or `null` for all current household members.
  The ID is category-prefixed and upserted to prevent duplicate pending
  deliveries. Call `cancel_household_notifications` when a source event is
  removed. Task reminders are excluded because their recipients and escalation
  are generated by the task system.
- Existing repository defaults remain: appointments one day before, food
  depletion seven days before, and medication at dose time. Assigned-task
  escalation stays one hour overdue. Notification preferences are per user and
  category; disabling one category cancels that user's pending reminders.
- For the demo, reminders for shared, unassigned care events (restocking,
  appointments, vaccinations and medication doses) go to all current household
  members. A feature may name one responsible recipient when its source record
  has one. Walk recording alerts remain with the walker unless Carol's existing
  walk flow requires a different recipient.
- Timestamps are stored as instants and displayed in the household time zone.
  Push delivery requires a supported browser/device, permission, subscription,
  server secrets, and a scheduled Edge Function. Until configured and tested on
  real phones, only task reminders queued on the server are implemented; push
  delivery and non-task reminder scheduling are not claimed as working.

### Academy

- Courses unlock sequentially after the previous module is completed.
- An explicit completion grants 10 XP once per household/module. Repeated taps
  cannot award XP twice. Each 50 XP advances one level; badges are awarded at
  1, 5 and 20 distinct completed modules.
- Any member's saved practice qualifies for the one household streak, counted
  by date in the household time zone. Deleting a member's own practice record
  removes that practice from the streak calculation. The shared module
  completion milestone, XP and unlock remain once earned, even if the author's
  practice note is later deleted; this avoids one member undoing family
  progress.
- A member can edit/delete only their own practice entries. Completion is an
  explicit action, not a side effect of opening a lesson.
- The demo starts with two short modules: Maria's daily care check-in and
  Carol's walking basics. Everyone can add a module using
  [the lesson template](academy/lesson-template.md); no unlicensed media or
  large content library is needed.
